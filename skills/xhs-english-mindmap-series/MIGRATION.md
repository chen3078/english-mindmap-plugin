# 迁移使用说明

版本：**2026.10.26.3**。包含家居篇门／窗户复盘、逐图检查、分支／问答编号分离、标题规则、统一发布检查，以及图库绑定、系列必填和生图证据记录。

## 安装到另一台电脑

1. 解压后，将整个 `xhs-english-mindmap-series` 文件夹放进目标应用实际使用的 skills 目录。保留 `assets`、`references`、`scripts`、`agents`、字体及许可证；不要只复制 `SKILL.md`。如果已有旧版，用完整文件夹替换，避免混装。
2. 让应用重新发现技能，并确认它读取的是这个版本的路径和 `release.json`。目标应用必须支持读取本地说明、打开图片、执行 Python，以及使用能接收参考图片的图像生成工具。压缩包不包含图像服务账号、密钥或生成额度。
3. 准备 Python 3.10 或更高版本。本版工具在 Python 3.11.1、Pillow 10.1.0 下测试。从解压的 skill 文件夹运行：

```text
python -m pip install -r requirements.txt
python -X utf8 scripts/verify_bundle.py
python -X utf8 scripts/test_regressions.py
```

自检会核对文件清单及 SHA-256、说明链接、Python 语法、参考 PNG 和依赖。它验证包完整性和工具条件，不证明新主题已经生成成功。修改包内文件后，需要重新发布并生成校验清单，不能继续声称是原版完整包。

## 给接收者的使用提示

```text
使用 $xhs-english-mindmap-series，主题：〔主题〕，系列：家居篇。
请实际读取本地 skill、家居篇门／窗户复盘和已通过的参考图；
先完成该主题内容及视觉方案，再按 skill 制作。
每张图片生成或修改后，逐项检查并记录；不符合模板就修改，
通过后再制作后续页面。不要把结构检查或生成对照图当成视觉通过。
```

这段提示便于调用；执行标准已经在 skill 内，接收者不必知道原来的聊天历史。新主题内容确认按 skill 的现有约定执行；已明确确认的内容不重复询问。

## 首次在新环境使用时

- 先实际打开 Key/Cup、Dog，以及家居篇适用的 Window 原图，确认图像工具收到了图片，不能只在提示词里写文件路径。
- 从新主题做完整导图、完整双语问答样张及代表性视频图（只做用户要求的格式）。分别按整页效果验收，再批量制作。只有导图的请求先停在导图。
- 家居篇先读 [home-series.md](references/home-series.md) 的失败对照表和生图前方案。固定材质、配色、轮廓和家居柔软感；布局适配新内容，不套用失败的标题侧栏、方块网格或重复大场景。
- 每张成品和每次修改都执行 [逐图检查](references/image-review.md)。图片、内容、参考图或标准改变，旧检查结果不能沿用。
- 每次实际生图后，由执行助手按 [生图证据说明](references/generation-evidence.md) 保存完整实际提示词、参考图快照、返回图片摘要和可取得的调用记录；本地排版／连线／缩放另外记录配方和父素材。只记录真实观察到的调用，不能为旧图猜写记录。记录本地关联通过不代表远端执行已独立验真。

从 skill 文件夹运行的检查命令：

```text
python -X utf8 scripts/review_image.py <主题目录> 01-cover.png --kind cover --home
python -X utf8 scripts/build_review_gallery.py <主题目录> --home
python -X utf8 scripts/check_visual_reviews.py <主题目录>
python -X utf8 scripts/check_release.py <主题目录>
```

前两个命令生成对照证据，不会自动判定美观。实际打开完整图片，逐项完成观察后按 `image-review.md` 记录结果；不能编造检查记录以让脚本通过。发布检查会拒绝缺失、待检查、失败、过期或漏掉家居标准的记录。

在逐图检查前，先注册实际生图／组合证据：`python -X utf8 scripts/generation_evidence.py <主题目录> <图片相对路径> --kind <类型> --spec <实际证据配置.json>`。配置及事件格式见生图证据说明。问答／视频每类只有一个已检查的代表样张，后续页绑定该样张和制作方法。缺少事件、提示词、实际参考输入或对应返回结果会被标为未验证并拦截；工具未提供的信息如模型名应如实留空，不得填造。

**最终记录完成后重建图库。** `review/gallery-binding.json` 会绑定全部当前图片、参考图、逐图记录／生图证据、HTML链接及总问答对照图。替换JPG、修改成品、改变证据或造成断链，都需要重新检查和生成绑定，不能仅靠同名文件或修改时间通过。

`check_release.py` 默认检查全套：完整版导图、无提示版、所有问答页、精确英文稿、每题视频图、文案、制作记录和图库。缺任何一项均失败。子集请求必须明确范围，例如 `--scope cover`、`--scope practice`、`--scope qa,text`、`--scope video`；视频范围包含配套英文稿。每次查看输出的 `CHECKED SCOPE`，子集通过不能当作全套通过。旧入口 `check_outputs.py` 现转到全套检查，`--cover-only` 转到导图子集；`check_video_outputs.py` 转到视频和英文稿子集。图像子集也要有制作记录、图库与有效逐图记录。不为通过全套检查制作用户未请求的内容。

新主题先按 [manifest-schema.md](references/manifest-schema.md) 准备内容：`groups` 管分支，`qa_items` 管问题，并通过 `group_id` 关联。杯子示例的9个分支对应13题，因此问答页范围、英文稿和视频编号均到13。新主题标题规则默认执行；保留已认可历史图的旧标题需要显式历史例外及理由，不会自动修改旧稿。回归测试使用临时模拟文件，验证程序行为，不作真实图片视觉通过判定。

所有新主题都必须在 manifest 明确填写 `"visual_family": "home"` 或 `"visual_family": "general"`，不再依靠名称猜测。漏填、无效值以及 `--home` 与 manifest 冲突均不能继续生产。仅保留已认可历史内容时，可显式使用 `manifest_mode: legacy` 并写明 `legacy_manifest_reason`；不得给新主题套用例外。机器检查核对规则、证据关联和记录，不能代替实际视觉判断，也不能独立鉴定远端服务是否真实执行。

## 本版验证范围

本版包含标准、参考图和检查工具，发布时验证完整打包、解压后引用及工具行为。**尚未完成迁移到另一位使用者账号后的新主题端到端生图验证**。因此不承诺一次生成必然达标；必须执行逐图对照、修改和验收，不得交付未通过图片。

## 2026.10.26.1 参考职责修复

必须读取 [参考图职责](references/reference-roles.md)。迁移包含18张认可图的职责和摘要清单、按成品类型的必需职责、实际样张继承检查、生图前预检，以及逐图／图库中的 Key/Cup 和本主题样张对照。缺少画风、构图、比例、适用家居处理或主体连续性中的任一必需项，都会拦截。旧的“任意一张参考即可”规则已移除。旧生图记录缺少新职责字段时会失效；应根据保留的真实调用重新核对，无法证明的保持未验证，不补造历史。

职责预检与21项临时模拟回归测试仅验证程序规则；不保证新主题首次美观，也不代表跨账号真实生图验证已经完成。

## 2026.10.26.2 问题生成更新

实际读取 [主题内容规划](references/content-planning.md) 和类别框架。牛奶篇形成的来源、特征、成分、种类、用途、取得保养、过程和扩展逻辑现用于各类别取舍；九个考虑维度不等于固定九题。新主题必须提供 content_plan；完整人工制品须有独立制作题及答案中的有序步骤，不能用材料题或清洁题代替。检查已接入原有内容、图像和发布流程。需要可靠来源的制作／加工等事实先核实。

镜子、牛奶、番茄及原有杯子／狗／公交车示例展示不同知识路径；镜子是内容回归示例，不是新生成的认可图片。旧认可主题不自动改写，缺少计划的显式历史兼容会标出“未按新标准验收”。本版保持现有18张认可参考图和视觉职责清单。

## 2026.10.26.3 连线成品与整齐检查

实际执行 [连线标准](references/branch-topology.md)。导图完整版和无提示版分别准备主体边界、分点目标及文字／插画保护区，运行 render_connectors.py 绘制最终连线并自动保存绑定。检查会重绘并核对最终PNG像素，缺少连线证据、改图、错格式、交叉、过度拥挤、绕行或穿过保护区均不能通过。

现有 Dog／Window 等认可图就是整齐参考，无需每个主题再索取。逐图还须独立填写 connector_neatness 的实际观察；几何通过不代表美学通过，区域声明是否准确也需查看原图。缺线或不整齐的成品不得发布。旧图不自动改写，也不补造连线记录；若要按新标准重新发布，需对所选素材作实际审查、绘制和记录。
