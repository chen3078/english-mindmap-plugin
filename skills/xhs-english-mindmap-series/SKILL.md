# English mind-map series · Key/Cup visual direction

Release **2026.10.26.3** adds mandatory connector-render bindings, final-pixel replay, geometry rejection and a separate whole-page connector-neatness inspection. The category-aware content planning and all existing illustration references remain. Follow [MIGRATION.md](MIGRATION.md) for installation and verify the full bundle.

Create a reusable topic package for English beginners. The accepted series look is the **Key/Cup** hand-drawn style. Use the owner-selected Cat mind map and approved Dog pages according to their distinct roles in [visual-system.md](references/visual-system.md). **Only the selected Cat mind map is approved as a Cat reference; Cat Q&A pages and Cat video images are not approved style references.** Use paths relative to this skill folder so the package works after it is copied to another computer.

**Format boundary before every image-generation call:** “picture-only / 无字练习图” means only the unlabeled *mind-map practice page* with its connected picture groups. A full-page Q&A image is always a finished page with all assigned English questions, English answers, Chinese questions, and Chinese answers. If a proposed image-generation prompt describes an empty Q&A page, blank cards, reserved text lanes, or text-free Q&A background, stop and change the production method before calling the tool. The image tool's output may appear in chat immediately, so a blank Q&A sheet is already an incorrect user-visible output even if text will be added later. Do not hand off, link, or archive such a sheet.

## Inputs and scope

- Accept a topic and, when provided, a category, audience (`children` or `adult_beginner`), facts, and personal examples. Infer ordinary defaults from the request; ask only when a choice would materially change the subject.
- Keep everyday words at their everyday scope. For example, `cat` covers ordinary domestic cats in homes, farms, streets, and outdoors; it does not silently expand to lions and tigers. Do not reduce broad topics to only the user's personal example.
- Use the same brand signature, `新陈代谢（英语版）`, small and unobtrusive on the labeled cover and bilingual pages. The picture-only page contains no readable text.
- Producing files or drafts does not authorize posting to Xiaohongshu. Deliver ready-to-publish assets and caption unless the user separately requests publication.

## Single source of truth

Before generating images, prepare one UTF-8 topic manifest under [manifest-schema.md](references/manifest-schema.md): `topic_en`, `topic_zh`, `category`, `audience`, `brand`, ordered `groups`, ordered `qa_items`, and `content_plan` with considered dimensions and actual question links. Groups define map branches; each question has its own ordered `id`, a `group_id` link and four bilingual text fields. One branch may have several questions. Every question-based tool uses the complete `qa_items` list; map connectors use group IDs. Historical files containing only `group.qa` remain readable without rewriting. The `assets/test-themes/` JSON files illustrate structure, not a fixed syllabus. Run `python -X utf8 scripts/check_manifest.py <manifest.json>` and resolve reported errors; review semantics separately.

For every **new** topic, set the first mind-map group's `heading_en` to exactly `What`. This is a short section label, not a question: never put `What it is`, `What is it?`, or a topic-specific full question on the mind-map branch. Put the natural full question only in that group's Q&A, such as `What is a cow?`. Apply this distinction to the manifest, rendered cover, caption's list of map dimensions, and any future examples. Historical approved images are visual references only; do not copy their old first heading or silently revise previously delivered topics.

For every **new** topic with a place/location dimension, set its mind-map `heading_en` to exactly `Where`, not `Where They Live`, `Where Dogs Live`, `Where It Goes`, or another sentence-like expansion. Keep the full natural location question only in that group's Q&A (for example, `Where do dolphins live?`). Preserve the location keywords and drawings under the short heading. Apply this to the manifest, rendered cover, caption's dimension list, and future examples; historical approved pictures are style references, not wording templates. Do not silently revise previously delivered topics.

For every **new plant** topic with a sunlight/water/soil growth-requirements dimension, set its mind-map `heading_en` to exactly `Needs`. Do not use sentence-like fragments such as `What helps it grow` or `What helps them grow` on the map. Put a complete natural question with a question mark only in that group's Q&A (for example, `What helps a tulip grow?`). The short map headings `What`, `Where`, and `Needs` are section labels, not questions. Apply the same wording to the manifest, cover, and caption dimension list.

Keep other mind-map branch labels short and natural as section names too: use `Movement`, `Help`, or `Eating` when those dimensions fit, rather than fragments such as `How Horses Move`, `How Dogs Help`, or `How They Eat`. Do not shorten the full, grammatical questions on Q&A pages.

Build content as a teacher: cover definition, appearance/parts, context, function or behavior, useful verbs, and one or two meaningful expansions. Use roughly six to nine groups when it fits; do not pad or cut a topic to hit a number. Add age, measurements, lifespan, safety, or technical facts only after checking a reliable source. Explain difficult words at beginner level. Make each question distinct and answerable from its associated pictures. Do not turn the Q&A into a long paragraph to memorize.

For animal topics, select the questions for the actual animal rather than copying Cat or Dog groups. A sound question is optional: use it only when the animal has a recognizable, accurately describable sound that is useful for beginners and can be meaningfully illustrated. Otherwise replace it with a more informative question about that animal; never add a sound group merely to fill a fixed template. Apply the selection criteria in `references/content-frameworks.md` before freezing the manifest.

Freeze the approved manifest before rendering. In this owner's one-animal-at-a-time workflow, present the complete bilingual Q&A for content review and wait for the user's content approval before image production. Approval of wording does not imply approval of visual samples. Derive the cover labels, Q&A pages, English-only Q&A text, one-question video stills, caption dimensions, and any summaries from that same manifest. If a fact changes, update the manifest first and regenerate affected outputs. Never invent a fact or alter a user-provided answer merely to fill a layout.

## Deliverables

1. **Cover:** a 3:4, 1086 × 1448 portrait English mind map. All learning text is English. Show one strong but **compactly sized** left main subject, organic branches, small literal illustrations for every group, clear headings and labels, and generous whitespace. Follow the accepted Carrot left-subject scale in `references/visual-system.md`; keep the right-hand mind-map groups at their established readable size. This is the Xiaohongshu first image.
2. **Picture-only practice:** the same concept order and the same recognizable illustrations/relationships as the cover. Remove the topic title, headings, labels, ages, numbers, brand text, **and the empty heading/number circles themselves**. Keep pictures, visual groupings, the one branch line per real group, and meaningful action arrows. Branches should lead toward their picture clusters, never end at a missing circle or in empty paper. It should let a learner speak from pictures, not from blank answer lines.
3. **Bilingual Q&A:** for a typical six-to-nine-question topic, plan **two or three 3:4 pages**, with roughly three or four questions on a page when their actual text fits. Decide the page split from the approved wording before generation; do not default to one or two questions per page and let the series grow page by page. Match the approved Dog/Rabbit Q&A pages' **finished appearance** (not merely their card colors), following [qa-layout.md](references/qa-layout.md). Preserve question order. English Q&A is primary; Chinese meanings remain phone-readable. Each question has a relevant integrated illustration. This is a preference, not permission to shrink text, crowd art, or use tiny thumbnails: if a long answer truly cannot fit, use a more spacious split and explain why. No knowledge-summary, teacher-additions, praise, next-focus, or connected retelling page unless the user asks.

   **The picture-only requirement applies only to the mind-map practice page. Every bilingual Q&A page must contain the exact English question, English answer, Chinese question, and Chinese answer for every group assigned to that page.** A complete all-in-one generated Q&A page or individually prepared art plus exact-text typesetting can be used; compare the **finished whole page** with the approved Dog page and verify every character against the manifest. The owner-approved Window Q&A pages demonstrate that all-in-one generation can match the Dog family when both checks pass; an editable layout is not automatically closer. **Do not generate a full-page text-free Q&A card sheet with an image tool that automatically displays its result in chat**: that exposes an unfinished layer that looks like a deliverable. If an unavoidable intermediate is displayed, identify it immediately as unfinished and follow it with the finished text-bearing page. When delivering a full topic, visibly present or directly link **every** final bilingual Q&A page; a ZIP link or cover alone is insufficient.
4. **English-only Q&A text:** one `qa-en-only.txt` containing the exact English question and answer from every ordered question, with no Chinese and no connected retelling. Generate it with `python scripts/export_english_qa.py <manifest.json> <qa-en-only.txt>`.
5. **Single-question video stills:** one independently composed, text-free, 3:4, 1086 × 1448 PNG per question ID in `video/01.png`, `video/02.png`, and so on. The count follows `qa_items`, not map branches. Each picture must illustrate its own answer and reserve the bottom quarter as quiet, empty paper for subtitles added in video editing. Use the approved Dog stills for subject scale and framing; use Key/Cup for illustration style. Do not make finished video stills by cropping a strip from the full mind map or enlarging a mini-icon. See `references/video-stills.md`.
6. **Xiaohongshu copy:** retain the existing ready-to-paste title and caption using the Feet-note structure in `references/caption.md` for a full Xiaohongshu package. Describe the actual page sequence and group count. If several visual variants are being compared, keep the copy the same unless the user requests otherwise.

If the user requests only a subset (for example video stills), make only that subset plus the manifest and exact English Q&A text needed to keep it consistent; do not create unrelated pages. A full-topic request produces all five learning outputs above plus the existing Xiaohongshu copy.

Save project assets in an ordered topic folder. Include the manifest and final prompt notes, use portable filenames such as `01-cover.png`, `02-picture-practice.png`, `03-qa-01-05.png`, `qa-en-only.txt`, `video/01.png`, and `caption.md`, and report their absolute paths. Do not overwrite existing work without the user's request.
