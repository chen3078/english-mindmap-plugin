# 主题问题生成与完整性检查

每个新主题在生成图片前阅读本文件。它把牛奶篇的提问逻辑扩展到其他类别；具体类别仍按 [content-frameworks.md](content-frameworks.md) 选择。问题用自然的初学者英语，图内分支标题保持简短。

## 目标：形成认识路线

从“它是什么”逐步展开到“从哪里来、有什么特点、怎样使用、怎样形成、还能变成什么”。每题教一个清晰的学习点，避免不同标题反复说同一事实。可以合并相近分支，也可以一组图片对应多题；分支数、题数不必相等。六至九组是布局参考，不是删掉重要知识的理由。

## 九项考虑，不是固定九道题

| content_plan键 | 需要考虑的问题 | 按主题适配 |
| --- | --- | --- |
| identity | 它是什么、属于什么 | 定义与基本范围 |
| features | 长什么样、摸／尝／听起来怎样 | 选择有用、可画的特征 |
| composition | 有哪些部件、材料、原料或营养成分 | 人工物品区分材料与部件；食品区分原料与营养 |
| types | 有什么种类、形态、状态或差异 | 生熟／成熟度与品种不可混为一谈 |
| use | 怎么使用、食用、操作或参与日常活动 | 除名词外，练习实用动词 |
| acquisition_care | 哪里取得、购买、放置，怎样保存或清洁 | 位置、取得、保养按实际需要选择，可分多题 |
| origin | 来源、原料起点、自然生长环境 | 来源与购买地点分开；可与定义共用同一道真实问题 |
| process | 怎样制作、加工、生长、变化或运输 | 需要有意义的过程，不能只列材料或一个地点 |
| extension | 能做成什么、特殊用途、比较或个人看法 | 选择有价值的扩展，不强加喜好题凑数 |

逐项标为 included（纳入）、omitted（适用但本课取舍）、not_applicable（不适用）。后两类必须解释本主题原因，不得统一写“可选”“不需要”“版面不够”。未选的维度不需要变成问题或占用分支。

## 类别与重要维度

- **manufactured_object 人工制品／家居物品**：完整主题必须覆盖定义、材料或部件、制作过程。主动考虑来源、种类、用途、购买和保养。制作题与使用／清洁题分开，`process.kind` 为 manufacturing；“Where is it made?”只有地点，不能独自替代过程。
- **food 食物**：延续牛奶篇，考虑来源、外观口感、成分／经核实的营养、种类、食用用途、购买保存、形成过程及延伸产物。完整主题至少有真实来源或过程；加工食品优先选择制作／加工，天然食物考虑生长、采收或从农场到商店。省略过程须写具体原因并人工复核；不强迫每个食物讲工厂制造。
- **animal 动物**：考虑栖息、食物、特征、能力与行为，过程可以是生长、生命周期或有阶段的行为。不能给动物套“制造”；声音、寿命、繁殖等按价值和准确性取舍。
- **plant 植物**：考虑部位、环境、需求、生长、开花结果和用途；“需要阳光”是生长条件，不能冒称已讲清完整生长过程。
- **transport 交通工具**：考虑构造、用途、路线、乘坐者、上下车、支付与安全。可选择制造或有步骤的乘坐／运行过程；不要求每个交通主题深入工厂制造。
- **other 其他**：记录分类理由和适合的路径。禁止为了跳过人工制品的制作题而改写类别或 profile。

若用户明确只要某个子话题，例如“只练镜子的外观和使用，不讲制造”，可用 focused 范围并保留用户原话。请求“只生成导图”只是输出格式范围，内容仍按完整主题规划；它不构成省略制作的授权。

## 材料与制作必须分开

- What is it made of? / What do we use to make it?：回答材料或原料。
- How is it made? / How do people make it?：回答有顺序的制作动作。
- How do we use/clean it?：回答日常操作或保养。

不能把 glass、wood、metal 三个材料名画上箭头就当作制作流程，也不能用“在工厂生产”替代实际制作步骤。完整人工制品应有清楚的 how-made 问题，答案可用一两句简短英语概括至少两个真实关键步骤；不需要讲复杂工业参数。材料题不可绑定为过程题。

例：镜子要区分玻璃／反光层／镜框，与在玻璃上形成反光层、再作保护处理的制作步骤。不同镜子工艺并不完全相同，应说明所选示例范围并核实，不写成所有镜子都使用同一材料。参考：[Guardian Glass 对镜面玻璃的制作说明](https://www.guardianglass.com/us/en/our-glass/glass-types/mirror-glass)。

## 内容清单格式

新主题在 manifest 添加 `content_plan`：

```json
{
  "version": 1,
  "profile": "manufactured_object",
  "scope": "full",
  "dimensions": {
    "process": {
      "status": "included",
      "question_ids": [8],
      "kind": "manufacturing",
      "steps": ["add a silver layer to glass", "cover it with protective paint"]
    }
  }
}
```

这里只展示 process 的局部格式。实际 dimensions 必须列全九个键；完整示例是 [镜子内容示例](../assets/test-themes/mirror-content.json)。每个纳入维度通过 `question_ids` 关联实际问题，每个问题至少归入一个维度；一个问题可服务多个维度，但不能重复列出同一问答来充数。

`steps` 是关联英文答案中按实际顺序出现的简短动作片段；至少两项。它用于把流程声明与真正写出的答案绑定，不能另编一套未出现在答案里的流程。每个片段应是有意义的动作，不得拆词凑步骤。食品允许 processing / cooking / growth / supply_chain；动物允许 growth / life_cycle / behavior；植物允许 growth / life_cycle；交通允许 manufacturing / operation / supply_chain。

`scope` 默认 full。focused 需要 `user_scope_instruction` 保存真实的用户范围要求；没有用户要求不能自行填造。当前分类能识别时 profile 必须对应；未知 category 应写 `profile_reason`。内容规划字段是可检查的声明，不是独立证明用户真的说过这句话或事实真的正确。

## 实际执行

1. 明确主题范围、类别和学习者程度，选择有价值的维度；列出纳入与省略理由。
2. 起草完整双语问答、每题学习点及插画要表现的内容；遇到工艺、营养、安全、储存等知识，先查可靠来源。
3. 检查问题之间是否重复；材料、来源、制造、使用是否被混淆；重要过程是否因版面／固定题数被删掉。
4. 把选择写进 content_plan，运行 `python -X utf8 scripts/check_manifest.py <manifest.json>`。缺少计划、制作遗漏、问题关联错误或流程步骤与答案不符会报错；已有发布流程也会调用此检查。
5. 对照实际问答人工检查：每个 included 维度确实问到了什么？省略理由是否合理？过程片段是否真实的有序动作？词句是否适合初学者且可以画出来？程序不理解所有同义问法，明确 how-made 问题有助于避免误判。
6. 按原有约定把完整双语问答提交用户确认，内容确认后再出图。新增维度同步到导图、无提示版、问答图、英文稿和每题视频素材，不只补一个分支标签。

## 示例与迁移

- [牛奶](../assets/test-themes/milk-content.json)：来源、加工、衍生食物。
- [杯子](../assets/test-themes/cup-multi-qa.json)：材料题与制作题独立，九分支十三题。
- [镜子](../assets/test-themes/mirror-content.json)：用于验证漏掉制作题会被拦截，不是已通过视觉验收的新成品。
- [番茄](../assets/test-themes/tomato-content.json)、[狗](../assets/test-themes/dog.json)、[公交车](../assets/test-themes/bus.json)：不同类别的选择和省略理由，不是统一题库。

既有已认可主题不自动改写。保留历史内容且缺少计划时，只有显式 legacy 模式及理由可兼容；检查输出会注明尚未按新内容标准验收。不能对新主题套历史例外，也不能为旧内容伪造先前检查记录。
