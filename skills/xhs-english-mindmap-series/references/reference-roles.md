# 参考图职责与继承校验

本文件定义每种成品需要什么参考，不把“参考过一张图”当成职责齐全。它与逐图视觉标准同时执行；程序能核对引用和职责，不能判断画面是否真的好看。

## 认可参考库的边界

机器清单是 [reference-roles.json](../assets/reference-roles.json)。现有18张参考图逐张绑定文件摘要和允许职责，不能仅靠改文件名或把 `role` 写成 `style` 获得画风资格。调用记录中的主要职责必须与认可职责相容；同一张图可以承担清单列出的多个职责。

| 参考图 | 可以控制 | 不可以代替 |
| --- | --- | --- |
| Key / Cup 两张整页 | 线条、纸张、铅笔／水彩质感、颜色处理 | 主体大小专用参考；新主题主体身份；对应格式的排版 |
| 指定 Cat / Dog 导图 | 分支、标题与图片的邻接、整页密度和节奏 | 新主题内容；Cat 问答和视频认可资格 |
| Carrot 两张指定图 | 左侧主体与整页的比例 | 手绘画风、问答排版、胡萝卜事实 |
| 指定 Window 导图 | 家居柔软舒适可爱处理、导图整页构图 | 强迫新主题加入窗帘、窗台、绿植或房间背景 |
| Dog / Lion / Window 无提示版 | 有连接、有语义分组、无字无空圈的成品结构 | 无连线制作底稿；原封不动复制其他主题的分支数量 |
| Dog 两张问答页 | 问答整页家族、文字层级、宽行、插画整合 | 仅选取粉蓝颜色或卡片边框 |
| Window 两张问答页 | 上述问答家族在家居篇的实际执行、家居处理 | 用其他 Window 失败稿替代 |
| Rabbit 两张指定问答页 | 三题页面安排 | 其他 Rabbit 页或视频的自动认可 |
| Dog 两张视频图 | 整幅主体／动作构图、字幕区 | 狗的形象、画风独立依据、问答页排版 |
| 本主题已通过的完整版 | 主体轮廓、配色、材质和图案一致性；可继承已证实的画风、大小和家居处理 | 无提示版拓扑、问答页布局、视频构图 |
| 本主题已通过的同格式问答／视频样张 | 已证实的本格式职责和主体连续性 | 另一种格式；后续页面免检 |

## 按成品分别要求

| 类型 | 必须覆盖的职责 |
| --- | --- |
| 完整思维导图 `cover` | `illustration_style` 画风 + `cover_layout` 导图构图 + `subject_scale` 主体比例 |
| 无提示版 `practice` | 画风 + `practice_layout` 无字连接结构 + 主体比例 + `subject_continuity` 本主题连续性 |
| 双语问答 `qa` | 画风 + `qa_layout` 问答整页排版 + 本主题连续性 |
| 每题视频图 `video` | 画风 + `video_framing` 整幅构图／字幕空间 + 本主题连续性 |
| 内部插画 `art` | 画风；最终成品仍须补齐其格式的全部职责 |

所有家居篇**成品**另需 `home_treatment`。普通主题不强行加入家居装饰。内部插画不是一个可以绕过最终成品检查的交付类型。表格给出最低职责覆盖；仍需实际查看 visual-system 要求的相关整页参考，不能把最低覆盖解释成忽略模板细节。

### 继承的条件

- 必须实际把本主题完整版／同格式样张作为图片输入。只写 `sample` 字段或在提示词里提到文件名不算。
- 完整版／样张的实际生图或组合记录必须有效；逐图视觉记录必须通过且早于后续页完成时间。缺少真实历史调用记录时不得补造，旧图只保留“证据未验证”状态。
- 完整版只传递已证明的画风、主体大小、家居处理及主体连续性，不传递问答／练习／视频的布局资格。
- 后续问答／视频必须同格式、同制作方法、沿用唯一代表样张。样张实际输入后可传递其已覆盖职责，不必每页重新输入狗的角色图。
- 每份记录保存职责来源、继承图、视觉记录和生图记录的摘要。任一内容改变，依赖检查失效；重新检查后才能继续。
- 组合制作递归核对实际父素材和配方。输入插画可以传递已证明的画风，排版职责可以来自实际查阅并记录的整页模板；不能把本地查阅记录冒称为模型收到的参考输入。

## 执行顺序

1. 读取本文件和对应格式标准，实际打开原图。明确本主题的主体设计、各参考图职责以及不应复制的事实／旧标题／装饰。
2. 保存计划实际传入的参考快照，生图前运行预检。例如在 skill 目录：

```text
python -X utf8 scripts/reference_roles.py <主题目录> --kind cover --references production/inputs/cup-style.png production/inputs/dog-cover.png production/inputs/carrot-scale.png production/inputs/window-cover.png
```

第一张问答／视频样张加 `--sample self`；后续页用 `--sample <样张相对路径>`，`--references` 必须包含该实际样张，`--method` 与实际方法一致。预检只核对计划，不能证明稍后的调用真的使用了它们。

3. 实际调用后按 [生图证据](generation-evidence.md) 注册；程序对实际输入链重新逐项核对，缺任一职责会明确报错，不能用预检记录替代。
4. 每张图片按 [逐图检查](image-review.md) 核对全尺寸文字／插画，并在350像素整页对照中检查结构、主体统一、手绘质感及节奏。图库同时展示 Key/Cup、对应格式模板、本主题完整版和实际沿用样张。职责覆盖通过不等于画面通过。
5. 失败则修正、重新记录和对照；全部实际检查后重建图库，再运行统一发布检查。

## 对整个英语口语学习项目的使用方式

2026-10-26 盘点项目57份主题内容记录、44种主题（含同主题复审版本），查看导图整页缩略对照，覆盖动物、植物、食品和12个家居主题。项目盘点与对照图保留在项目 `.skill-audit/reference-role-completion/`，迁移不依赖该本机路径。

项目中“存在图片”、文件名叫 final、脚本写 pass、或用户确认内容文案，都不是该图成为认可模板的证据。旧 Door/Window 失败稿、revisions、样张测试、Cat 问答／视频不能混入正向参考库。新增参考必须确认**具体文件及认可范围**、实际查看原图、指定职责／适用格式、记录摘要、重新打包并测试。现阶段继续使用已认可的18张图，不将其他项目图片自动提级。

跨类别可借鉴有用的局部表达，但新主题的物理结构、动作、用途和问题来自本主题内容清单。内容参考不能冒充排版参考。杯子的 Hello Kitty、雨伞的白兔图案属于各自已选主体设计，不能自动带到床、冰箱或植物主题。
