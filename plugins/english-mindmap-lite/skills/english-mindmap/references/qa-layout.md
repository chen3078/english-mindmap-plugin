# Bilingual Q&A page layout

Select the production method and follow the execution order in [production-workflow.md](production-workflow.md). This file defines the final-page appearance and its checks; it does not mandate editable typesetting for every topic.

**Output rule:** There is no “picture-only Q&A” format in this series. Every generated or delivered full Q&A page must already include its four complete bilingual text fields per question. Do not generate a full-page blank Q&A card/background image, including as a temporary layer for later typesetting. For editable layouts, prepare only isolated per-question illustrations and render the complete text-bearing page before showing it to the owner.

The canonical visual target is `../assets/approved-dog/qa-01-04.png` and `qa-05-08.png`. For a home-object topic, also use the owner-approved `../assets/approved-window/qa-01-04.png` and `qa-05-08.png` as finished four-row examples. The retained supplementary Rabbit references are `../assets/approved-rabbit/qa-01-03.png` and `qa-06-08.png`, both three-question pages. Cat Q&A pages and other Rabbit Q&A pages are not approved references. Compare the final rendered page, not just the source HTML, with the relevant accepted raster at phone size.

## Full-page sample gate

Before making the remaining Q&A pages, take the frozen manifest's **actual bilingual questions and answers** and render one complete 1086 × 1448 sample page with its real illustrations. Choose a page whose text length and art demand are representative of the topic; include a long answer if one exists. A single row, placeholder text, wireframe, or self-made blank template is not a valid sample. Place the exported sample beside an approved Dog **whole page** at the same phone-size width. Check the header, apparent English lettering size and stroke weight, Chinese readability, row spacing and fill, illustration integration, and overall page density. Re-render until the complete page reproduces the approved family, then use that successful sample as the local reference for the remaining pages. Record the reference, sample filename, observations, revisions and pass/fail in `prompt-notes.md`. If no sample passes, do not batch-render or call the Q&A set complete.

For a home-object topic, also place the sample beside the approved Window whole page. The older Window Q&A drafts copied the card colors but rendered a much heavier, denser page; matching palette or four-row count is not enough. The approved Window Q&A used actual Dog full-page art plus the accepted Window cover as image references, generated a **complete text-bearing page**, checked every English and Chinese field against the manifest, and then used that successful page as a reference for the second page. This is a viable method, not a guarantee that generated lettering is correct. Reject or repair any misspelled, omitted or distorted character.

Use the Door/Window failure-to-requirement table in [home-series.md](home-series.md) for home topics. Inspect whole-page template match, type hierarchy/readability and art integration as separate criteria. Soft cards and correct source text are not substitutes for the actual finished layout. Record the concrete change when a failed page is remade; do not repeat the same composition under a new filename.

For complete-page generation, request the complete bilingual page in the image call. For separate-art typesetting, generate **individual Q&A illustrations** and then render the complete text-bearing page locally. In neither method generate a full-page empty card sheet. A blank Q&A sheet is an unfinished production layer and is likely to be mistaken for the final teaching page. Text-free deliverables are the mind-map practice page. For each Q&A page, verify the final PNG visibly contains the English question, English answer, Chinese question, and Chinese answer for every assigned group before it is shown as a finished page.

## Reusable page structure

- Canvas: 1086 × 1448, portrait 3:4, warm paper background.
- Header: large hand-drawn `<TOPIC> · Q&A <first>–<last>`, dark brown with restrained coral and blue accents.
- Body: stacked full-width horizontal rows. For a typical six-to-nine-question topic, **aim for two or three pages total**, normally three or four questions per page when the actual bilingual text fits. Plan the split before generation. Dog's four-row pages work for short answers; the retained Rabbit pages illustrate three-row layouts. A long answer may need a larger row. Keep this page-count preference subordinate to phone readability and whitespace; explain any necessary extra page rather than silently defaulting to many two-row pages.
- Each row: a colored number circle at left; English question and answer in dark, **large, bold** handwritten type; Chinese question and answer below their English counterparts in smaller but still **phone-readable** type; a related hand-drawn illustration integrated at right. Use blush, pale blue and muted yellow row washes or borders like the Dog pages. Verify the text's apparent size and stroke weight against the actual Dog raster, not just CSS pixel values. Make the text the primary information; art must not force the type smaller.
- Text and illustration must never intersect. Illustration edges should blend into the row background; no pasted rectangular screenshot, mini-map strip, stray branch, or separate framed thumbnail.
- Keep the brand signature small near the bottom edge. Do not add knowledge-summary, teacher praise, next-focus, or a memorized paragraph.

## Editable layout helper

`scripts/build_qa_pages.py` is an **optional fallback**, not the definition of the Dog style. It creates editable HTML/CSS pages from the approved manifest and one independently prepared, transparent or edge-blended illustration per question in `<topic-folder>/qa-art/01.png`, `02.png`, etc. When generating each illustration, request the accepted Dog/Key/Cup drawing style, the current topic subject, the answer's visual details, and an isolated vignette with no printed text or opaque card background. The CSS is in `assets/templates/qa-page.css` and uses the bundled fonts. The helper keeps text and art in separate grid areas; it does not draw, approve, or repair illustrations. Render the HTML to 1086 × 1448 PNG and inspect it beside the Dog raster at phone size. If the lettering looks smaller/thinner, the art sits as a pasted patch, or the page feels like a different series, reject it and revise the composition; do not present it as Dog-matched merely because the wording is exact.

The helper's automatic pagination is only an initial suggestion. After reviewing the real text and art, use `--page-sizes` for the planned split where it stays readable (for example, an eight-question topic may use `3,3,2`; thirteen real questions need more pages). The counts must sum to the complete question count, not map branches. `qa-art/NN.png` and page ranges use question IDs under [manifest-schema.md](manifest-schema.md). If one row truly needs more space, increase page count rather than lowering text size.

Apply the method-selection rule in [production-workflow.md](production-workflow.md). Neither method earns approval automatically. For complete-page generation, compare every English and Chinese character against `manifest.json`, and repair or regenerate any page with missing, distorted, or incorrect text. For editable layouts, reject pages that look like mechanically filled templates or pasted-in art. In either method, the final rendered page must pass the same visual and text checks at phone size.
